Build on sovereign memory

Everything you need to install Smritium, ingest your corpus, and query it — locally, verifiably, offline.

Overview

Smritium is a local-first memory substrate. Four subsystems cooperate on your machine:

IngestionContent-addressed, deduplicating document capture with deterministic chunking. Same inputs → same memory state, always.
StorageLocal embeddings (MiniLM-class via sentence-transformers), vectors in LanceDB on disk, metadata in SQLite as the source of truth.
RetrievalThe Context Rehydrator fuses semantic, temporal, and relational signals into one ranked context window.
SynthesisPluggable inference (Ollama local / remote optional / mock) with chunk-ID citations and low-confidence abstention.

Installation

# macOS / Linux
curl -fsSL https://smritium.ai/install.sh | sh

# Windows
winget install DataFrontier.Smritium

# verify — every check must pass without a network connection
smritium doctor

Builds are signed and notarised. smritium doctor is the clean-machine acceptance check: python runtime, local embedding model, vector store, metadata schema, and inference availability.

Quickstart

# 1. ingest a folder (idempotent — safe to re-run)
smritium ingest ~/Documents/notes

# 2. search the raw substrate
smritium search "kestrel contract"

# 3. ask with attributed synthesis
smritium ask "what did we agree with Kestrel on payment terms?"
→ Net-45, revised from Net-30 on 12 May. [1] kestrel_msa_v2.md · chunk 4be1…

# 4. keep it current, consent-gated
smritium watch ~/Documents/notes
smritium inbox   # review & approve ambient captures

CLI commands

doctorEnvironment & health check; PASS/FAIL per subsystem. Exit code 0 = fully sovereign.
ingestContent-addressed ingestion of files/folders. Unchanged files are no-ops; edits diff at chunk level.
searchDirect retrieval over the substrate (no synthesis). Supports filters by source, time range.
askRetrieval + attributed synthesis. --debug shows per-signal contributions; --engine local|remote|mock selects inference; --compare runs local vs remote side by side.
sourcesList, enable, or revoke capture sources.
tasksExtracted action items across your corpus.
watchAmbient filesystem watcher with debounce, dedup, delete-handling.
inboxApproval queue for ambient captures — nothing enters durable memory without consent.
knowledgeEntity/knowledge-graph operations. --graph --out graph.html exports a self-contained visualization.
metricsLocal, privacy-preserving usage metrics.
writeDraft in your own voice, grounded in your memory.
demoLoad a demo corpus for evaluation.

Configuration

Sources and features are declared in sources.yaml and features.yaml in your Smritium home directory. Everything is inspectable — the databases are ordinary SQLite and LanceDB files you own.

Deterministic chunking

Chunk boundaries and hashes are a pure function of (chunk text, chunker config) — never of ingestion order, path, or wall-clock time. Consequences:

Stable citationsA chunk ID cited last month resolves to identical evidence today.
Cache-safe re-embeddingOnly genuinely new chunks are ever re-embedded.
ReproducibilityIndependent re-ingest of the same corpus reproduces 100% of chunk hashes. See the reproducibility audit.

Context Rehydrator

Retrieval fuses three orthogonal signals — semantic (dense vectors), temporal (calendar/recency weighting), relational (personal knowledge graph) — into a single ranked context window. The fusion-vs-semantic-only delta is measured in our published evals (Recall@k, MRR, nDCG).

smritium ask --debug "what changed in the Q1 close?"
chunk 9f31…  score 0.87  = semantic 0.52 + temporal 0.24 + relational 0.11
chunk 77aa…  score 0.79  = semantic 0.61 + temporal 0.08 + relational 0.10

Consent & the approval inbox

Ambient events (watcher, mail, calendar) route to a staging area first. An isolation guarantee — verified by test — ensures nothing reaches durable memory pre-approval. Sources are explicitly enabled and revocable at any time.

Inference engines

Synthesis is pluggable: local (Ollama), remote (optional), mock (testing). If no engine is available, retrieval still answers — the system never hard-fails on missing inference.

Self-hosting notes

There is nothing to self-host — that's the point. Smritium is the self-hosted deployment, on every machine, at every tier, from the free core up. Multi-device sync (Pro) runs over LAN or encrypted P2P between your own devices; no third-party cloud transits your data.
