Why Smritium

Cloud memory products rent your own mind back to you. Smritium inverts the architecture.

Mainstream memory APIs externalize your corpus to a provider, embed it remotely, and meter your recall by the token. Smritium keeps capture, embedding, retrieval, and reasoning on-device — and treats any cloud model as an optional, swappable accelerator, never a dependency.

⌂

Sovereign by construction

Embeddings computed locally. Vectors in an on-disk store. Metadata in local SQLite. No corpus byte is required to leave the device for the system to function — not as a setting, as an architecture.

⛓

Verifiable memory

Every answer is traceable to its source chunks via content-addressed identifiers. Retrieval is attributed, not just plausible. When confidence is low, Smritium abstains instead of hallucinating a citation.

◌

Graceful degradation

Reasoning is pluggable — local models via Ollama or an optional remote model. If inference is unavailable, the retrieval substrate still answers. No GPU, no API key, no problem.

The Context Rehydrator

Recall is a sensor-fusion problem, not a cosine distance.

Ranking on vector similarity alone misses how humans actually remember. Smritium fuses three orthogonal signals into one ranked context window — and shows you each signal's contribution with smritium ask --debug.

Content-addressed ingestion

Documents are hashed on content, not path. Re-ingesting an unchanged file is a no-op; edits are diffed at chunk level. The same inputs always yield the same memory state — idempotent, reproducible, trustworthy.

Questions, answered

Does any of my data ever leave my machine?

Not for the system to function. Capture, embedding, storage, retrieval, and local reasoning are all on-device. If you choose to use a remote model for synthesis, only the minimal prompt context crosses — and with Membrane, it's redacted, approval-gated, and logged.

What happens if I'm offline or my API key expires?

Smritium never hard-fails on missing inference. Retrieval always works; a local model via Ollama keeps full ask/synthesis working with zero connectivity.

How is this different from Supermemory or other memory APIs?

They're cloud infrastructure — your corpus is uploaded, embedded remotely, and metered per token; self-hosting starts at premium tiers. Smritium is local-first by construction: private deployment is the default, citations are content-addressed and reproducible, and pricing is flat. Different architecture, different promise.

What does "verifiable memory" actually mean?

Chunk boundaries and hashes are a pure function of content and chunker config — not ingestion order or timestamps. Re-ingesting the same corpus reproduces 100% of chunk hashes, so a citation you got last month still points at exactly the same evidence today.

What's "Smritium" mean?

From Sanskrit smṛti (स्मृति) — "that which is remembered." Built in Karnataka, India, where memory has been treated as sacred infrastructure for about three thousand years longer than the cloud.
